Sitemap Page - sitemap.html

Page Purpose

This page shows a visual diagram of the site so users can see how every page connects to each other, and click straight through to any page from the diagram.

HTML and SVG Implementation

The diagram is built using an inline <svg>. Each page is represented by a <g> element containing a box (<rect>) and a text label, wrapped inside an <a> tag so the whole box is clickable. <line> elements are used to draw the connecting lines between pages.

CSS Implementation

Embedded CSS colours the Home page box differently from the other pages, adds a hover effect that darkens the boxes, and applies a gold "highlighted" style to the main pages when the button below is clicked. A legend explains what each colour means.

JavaScript Implementation

A script selects the #highlight-main-btn button and all the main page boxes using querySelectorAll(). When the button is clicked, it adds or removes a .is-highlighted class on each of those boxes to change their colour.

Accessibility

Each box in the diagram has tabindex="0" so it can be reached using the keyboard, and the SVG includes a text description so screen reader users who can't see the diagram still understand how the pages connect.

Contact / Enquiry Page - contact.html

Page Purpose

This page lets students fill in a form to ask Zone29 a question about careers support, internships or graduate schemes.

HTML Implementation

The form uses two <fieldset> groups with a <legend> each — "Details" and "Your Enquiry" — to group related fields together. Each input has its own <label>, and the fields include a text input for the name, an email input, two dropdown <select> menus, and a <textarea> for the message. There is a submit button and a reset button at the bottom.

CSS Implementation

Embedded CSS styles the fieldsets with rounded borders and a bold navy legend, gives all inputs and the textarea a consistent border and padding, and styles error messages in red below each field. The status message turns green when the form is filled in correctly.

JavaScript Implementation

A script listens for the form's submit event and uses event.preventDefault() to stop the page from actually submitting. It checks the name, email and message fields using querySelector(), and shows an error message next to any field that is empty (or if the email doesn't contain an "@"). If everything is filled in correctly, it shows a success message; otherwise it tells the user to fix the errors above.

Accessibility

Every field has its own <label>, and the two fieldsets use <legend> so screen readers announce which group a field belongs to. The status message uses role="status" so screen readers automatically announce whether the form was submitted successfully or has errors, without the user needing to find it manually.

Common Template, CSS and JavaScript

Every main page shares the same header, navigation menu, footer and go-to-top button, all controlled by one shared file, style.css. Challenges and Lessons Learned

A few issues came up while building the site. Some links pointed to the wrong filenames (like a leftover reference to an old file name instead of Page_Editor.html), which meant they didn't work until the filenames were fixed. Some images didn't show up because they were saved inside an images folder but the code was missing that folder name in the path. The W3C validator also caught missing spaces between HTML attributes, and pointed out that a couple of sections were missing headings, which I fixed by adding hidden headings for screen readers. This taught me to double check file names and image paths carefully, and to always run pages through the validator.

Accessibility and Janet Compliance

Every page uses one main heading, clear smaller headings underneath, and alt text on all images. Buttons and links can all be used with the keyboard, and the current page is always shown clearly in the navigation menu.
